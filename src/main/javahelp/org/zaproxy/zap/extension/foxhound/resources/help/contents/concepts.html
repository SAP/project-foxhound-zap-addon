Core Concepts

This page explains the fundamental concepts of taint tracking and how Foxhound uses them to detect vulnerabilities.

Taint Tracking Fundamentals

What is Taint Tracking?

Taint tracking is a dynamic analysis technique that monitors how data flows through an application at runtime. Data from untrusted sources (user input, URLs, cookies, etc.) is marked as "tainted", and the system tracks where this tainted data flows.

When tainted data reaches a dangerous operation (a "sink"), this indicates a potential security vulnerability.

How Foxhound Implements Taint Tracking

Foxhound is a modified Firefox browser with JavaScript engine instrumentation:

  • The JavaScript engine is modified to track taint information on strings and other data types
  • When data comes from a configured source, it's automatically marked as tainted
  • As data flows through operations (concatenation, substring, assignment, etc.), taint information propagates
  • When tainted data reaches a configured sink, Foxhound records the complete flow chain
  • Flow data is sent to ZAP via HTTP for analysis and alerting

Source Tags

Sources are categorized with tags that help identify attack vectors:

  • URL - Data from URLs (most common for DOM XSS)
  • INPUT - Data from form inputs
  • STORAGE - Data from storage APIs (for stored XSS)
  • NETWORK - Data from network requests

Why Sources Matter

Understanding sources helps identify:

  • Attack vectors: How attackers can inject malicious data
  • Risk level: URL sources are easily controlled by attackers (high risk)
  • Exploitation scenarios: Different sources enable different attack types

Sinks

Definition

A sink is a dangerous operation where tainted data could cause harm. Sinks are operations that execute, render, or otherwise use data in ways that could lead to code execution, injection, or other vulnerabilities.

Sink Tags

Sinks are categorized by vulnerability type:

  • XSS - Cross-site scripting sinks (most dangerous)
  • JAVASCRIPT - JavaScript code execution
  • HTML - HTML injection
  • CSS - CSS injection
  • URL - URL manipulation (open redirects)

Why Sinks Matter

Sinks determine:

  • Vulnerability type: What kind of attack is possible
  • Impact severity: Code execution sinks are highest risk
  • Exploitation difficulty: Some sinks easier to exploit than others

Taint Flows

Definition

A taint flow is the complete path that tainted data takes from a source to a sink, including all intermediate operations. Foxhound captures taint flows as TaintInfo objects.

TaintInfo Structure

A TaintInfo represents one complete flow and contains:

  • ID: Unique identifier
  • Timestamp: When captured
  • URL: Page where flow occurred
  • Sources: List of source strings (e.g., ["location.hash"])
  • Sink: The dangerous operation (e.g., "eval")
  • Sink Params: Parameters passed to the sink
  • Taint Ranges: Specific substrings and their flow chains
  • Stack Trace: Call stack when sink was reached

TaintRange Structure

A TaintRange represents a specific substring of tainted data within the sink parameters:

  • Begin/End: Character positions (e.g., 0-15)
  • String: The tainted substring
  • Flow Chain: List of TaintOperations showing how data got here

TaintOperation Structure

A TaintOperation represents one step in the data flow:

  • Operation Type: What happened (e.g., "string_concat", "assign", "charCodeAt")
  • Location: File/URL where operation occurred
  • Line Number: Line in source code
  • Function: JavaScript function containing the operation
  • Result: Result of the operation (if applicable)

Flow Visualization

The Foxhound panel visualizes flows hierarchically: 

TaintInfo (complete flow)
  └─ TaintRange (tainted substring)
      ├─ TaintOperation 1 (first step)
      ├─ TaintOperation 2 (second step)
      ├─ TaintOperation 3 (third step)
      └─ ... (additional steps)

Example Flow: 

Source: location.hash = "#alert('xss')"
  → Operation 1: substring(1) removes "#" → "alert('xss')"
  → Operation 2: assign to variable x
  → Operation 3: string_concat with other data
Sink: eval(x) executes the string

Vulnerability Detection

How Taint Flows Indicate Vulnerabilities

A taint flow indicates a vulnerability when:

  • Tainted data originates from an attacker-controlled source (e.g., URL)
  • The data flows through the application without proper sanitization
  • The data reaches a dangerous sink (e.g., eval, innerHTML)
  • The source + sink combination enables an attack

Source + Sink Combinations

Different combinations indicate different vulnerability types:

Example: DOM XSS Detection

Foxhound detects DOM XSS when:

  1. Source: User controls data via URL (location.hash, location.search, etc.)
  2. Flow: Data flows through application without encoding/sanitization
  3. Sink: Data reaches code execution sink (eval, setTimeout, innerHTML, etc.)
  4. Result: User can inject and execute arbitrary JavaScript

Concrete Example: 

URL: https://example.com/#<img src=x onerror=alert(1)>

Flow:
1. location.hash reads "#<img src=x onerror=alert(1)>"
2. substring(1) removes "#" → "<img src=x onerror=alert(1)>"
3. innerHTML sink executes: element.innerHTML = tainted_data
4. Browser parses HTML and fires onerror event → alert(1)

Alert: DOM XSS vulnerability raised by Foxhound
